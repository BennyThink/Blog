# 03 · 主题与功能移植

状态：首轮主题与核心功能已实现，完成编译、构建及代表页面验证；特殊页面/短代码与所有者配置验收仍待完成。

目标：将确认要保留的视觉和交互移植到 EmDash，不直接运行 WordPress 主题。

## 范围与实施边界

- 以 [第 02 步](02-inventory.md) 已确认功能清单为准，逐项记录实现位置、验证结果与差异，不因下方清单简写而遗漏功能。
- 以旧站公开页面和本地主题为视觉依据，保留 frame/band；文章详情按所有者最新确认使用旧站两栏，覆盖模板原有三栏要求。
- 仅提供站长登录入口与状态，不建设读者账号系统。
- 配置入口由开发实现，实际配置值由所有者填写；不以缺少配置值阻塞开发。
- 不迁移或修改现有评论；垃圾评论提交过滤、评论占位文本与混合头像仍须实现。
- Telegram token 仅放服务端秘密配置；历史文章导入不得触发批量通知。
- 不执行旧 WordPress PHP、不修改线上设置、不发布或切换流量。

## 实施顺序

1. 补齐首页、列表、文章、独立页面、搜索、导航、侧栏和移动端参考，核对旧主题资源许可与依赖。
2. 查阅当前 EmDash 文档，逐项确定内置能力、模板组件或插件方案，以及配置入口和服务端校验方式。
3. 实现主题与页面，再接入公告、分享、面包屑、作者、目录、版权、社交、pangu 和图片灯箱。
4. 实现登录状态、SEO、头尾注入、评论过滤与头像、Telegram 发布通知，并逐项验证。
5. 完成跨设备、主题模式、键盘与长文检查，移交第 04 步验收。

### 配置方法

- 在 EmDash 管理后台的插件列表中打开“土豆 · 主题与功能”（`dmesg-theme`）的设置。配置存入现有数据库中的插件命名空间。
- 公告为每行一条纯文本；头部、统计、页尾三个字段接受所有者信任的 HTML。社交地址为空时不显示。
- 站名、tagline、菜单、widget 和作者介绍仍使用 EmDash 原有管理入口，不重复保存。
- Telegram 配置：在插件设置填写 Bot Token、频道 ID 和 Owner ID；开启后，首次文章发布或新评论时插件会用 EmDash 站点 URL 调用 Telegram `setWebhook` 注册 Webhook。站点须有公网 HTTPS 域名，Owner 须先主动打开 Bot 私聊。首次发布只通知一次；文章更新及导入不通知。测试没有连接真实 Telegram。
- `COMMENT_BLOCKED_IPS` 为逗号分隔的原始 IP；反向代理部署时先核对 adapter 的地址来源。IP 哈希规则可在插件中填写。
